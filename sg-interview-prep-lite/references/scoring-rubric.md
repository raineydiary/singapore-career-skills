# 面试评分 Rubric

使用六个 job-related 维度，每项 1 至 5 分。评分必须引用候选人回答中的具体证据。分数用于训练排序，不代表 offer 概率。

## 六个通用维度

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| Relevance | 没有回答问题或偏题 | 回答了核心问题，但与岗位连接较弱 | 直接击中问题，并清楚连接岗位需要 |
| Evidence | 只有自评或空泛结论 | 有例子，但 ownership 或结果不够清楚 | 使用可核实例子，ownership、行动和结果边界清楚 |
| Structure | 难以跟随、顺序混乱 | 基本可跟随，但路标或重点不稳定 | 结构自然、重点突出、时间控制好 |
| Specificity | 大量泛词和未解释概念 | 有部分细节，但关键 decision 不够具体 | 关键行动、判断、取舍和范围都具体 |
| Delivery | 听题或表达明显影响理解 | 基本清楚，有少量冗余或背稿感 | 清楚、自然、专业，会倾听并回应追问 |
| Role-specific reasoning | 缺少岗位方法或判断 | 使用了基本框架，但验证和取舍有限 | 方法正确，能验证、解释限制并连接业务或技术影响 |

不要评分口音、国籍、年龄、性别、婚姻、残障等非岗位相关特征。语言反馈只针对清晰度、结构、专业用词、听题和互动。

## 技术题附加检查

- Requirements / assumptions
- Approach and correctness
- Verification / tests / edge cases
- Complexity、scale 或 performance
- Alternatives and trade-offs
- Debugging and communication

记录候选人完成程度：独立完成、轻提示后完成、高度引导后完成、未完成。

## Data / Case 附加检查

- Objective and metric definition
- Structure / issue tree
- Assumptions and data quality
- Calculation and units
- Insight / “so what”
- Synthesis、risk 与 next step

## Product / Portfolio 附加检查

- User or stakeholder definition
- Evidence-backed problem
- Decision rationale and prioritisation
- Success metrics and guardrails
- Validation / experiment
- Limitation and reflection

## 反馈报告模板

### 整轮概览

用 2 至 3 句总结表现，不虚构面试官感受或录用概率。

### 六维评分

列出六项分数，每项引用一句候选人回答作为证据。

### 最强两点

指出可继续复用的具体行为。

### 最大三个风险

按“问题 → 为什么影响面试 → 下次怎么做”写。

### 逐题复盘

每题记录：评估维度、使用框架、证据、遗漏、追问表现、是否获得提示。

### 重答示范

只使用已核实的候选人素材。资料不足时给 skeleton 和 open questions，不生成虚构 final answer。

### 下一轮训练

给出三项可在 15 至 30 分钟内完成的动作，例如重录一分钟自我介绍、补齐一个 STAR 的 Result、完成一题 SQL dry run 或做一次 case synthesis。
